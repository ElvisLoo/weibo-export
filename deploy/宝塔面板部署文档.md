# wb.jikegang.com 宝塔面板部署文档（交给 workbuddy 执行）

> 目标：把「极客港 · 微博导出」网页版部署到阿里云 ECS，通过宝塔面板管理，
> 用腾讯云 EdgeOne（EO）接入域名 wb.jikegang.com 并隐藏源站 IP。
> 主站 www.jikegang.com 不受影响，本部署只新增一个独立站点 wb.jikegang.com。

---

## 〇、给 workbuddy 的任务摘要

- 在阿里云 ECS（已装宝塔）上部署一个 **Python FastAPI** 项目
- 新建站点 **wb.jikegang.com**，用宝塔的 **Python 项目管理器** 跑起来
- 用宝塔的 **Nginx** 给该站点做反向代理（端口 8765）
- 后续在腾讯云 EO 控制台把 wb.jikegang.com 接入，回源到这台 ECS

预计耗时：**20–30 分钟**。全程在宝塔面板操作，少数命令用宝塔「终端」执行。

## 二、上传项目

### 1. 上传压缩包
把 `weibo-export-deploy.tar.gz` 上传到 ECS。

- 方式 A（宝塔文件管理）：左侧「文件」→ 进入 `/www/wwwroot/` → 点「上传」→ 选择压缩包
- 方式 B（命令）：本机执行
  ```bash
  scp weibo-export-deploy.tar.gz root@<ECS_IP>:/www/wwwroot/
  ```

### 2. 解压
宝塔「文件」进入 `/www/wwwroot/`，右键压缩包「解压」，得到目录：
```
/www/wwwroot/weibo-export/
```

> 如解压出的是 `weibo-export/weibo-export/`（双层），把内层内容移到外层，确保 `/www/wwwroot/weibo-export/weibo_export/`（引擎包）存在即可。

## 三、用 Python 项目管理器创建项目

宝塔左侧「网站」→ 顶部切到「Python项目」→「添加Python项目」，按下列填写：

| 字段 | 填写值 |
|---|---|
| 项目名称 | `weibo-export` |
| 项目路径 | `/www/wwwroot/weibo-export` |
| 启动文件 | `run.py`（若管理器要求模块启动，见下方「启动方式」） |
| Python 版本 | 选 **3.10** 或更高（管理器里装好的版本） |
| 端口 | `8765` |
| 启动方式 | 命令行启动（见下） |
| 是否安装依赖 | 勾选，依赖文件选 `/www/wwwroot/weibo-export/requirements.txt` |
| 映射域名 | `wb.jikegang.com` |

### 启动方式（关键）

Python 项目管理器常用两种启动写法，**优先用模块启动**：

- **模块启动（推荐）**：
  - 启动方式选「命令启动」
  - 启动命令：`python -m weibo_export.server --host 127.0.0.1 --port 8765`
- **若管理器强制要「启动文件」**：启动文件填 `run.py`，端口 `8765`。

> run.py 默认监听 `127.0.0.1:8765`（仅本机），由宝塔 Nginx 反代对外，**安全**。
> 如果面板把项目跑在了 `0.0.0.0`，请在「启动命令」里显式写 `--host 127.0.0.1`。

### 创建后验证

1. 管理器里项目状态应为「运行中」
2. 宝塔「终端」执行：
   ```bash
   curl http://127.0.0.1:8765/api/status
   ```
   应返回包含 `"brand":"极客港"` 的 JSON，即服务正常。

## 四、新建 Nginx 站点 + 反向代理

### 1. 新建站点
宝塔「网站」→「添加站点」：
- 域名：`wb.jikegang.com`
- 根目录：默认即可（如 `/www/wwwroot/wb.jikegang.com`）
- PHP版本：**纯静态**
- 不创建数据库、不创建 FTP

### 2. 配置反向代理
点该站点「设置」→ 左侧「反向代理」→「添加反向代理」：
- 代理名称：`weibo-export`
- 目标 URL：`http://127.0.0.1:8765`
- 发送域名：`$host`

保存后，宝塔会生成一段基本反代配置。**但默认配置会让进度轮询卡顿**，需要补充关键指令。

### 3. 追加关键 Nginx 指令（重要）

点站点「设置」→「配置文件」，在 **`server { ... }` 块内**、反代 location 里补充下面内容。
宝塔反代默认生成的 location 形如 `location ^~ / { proxy_pass ... }`，把它替换/补充为：

```nginx
# ---- wb.jikegang.com 反向代理（适配腾讯云 EO，动态接口不缓冲）----

# 透传真实 IP（EO 回源会带这些头）
proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;

# 客户端上传（Cookie 不大，1m 足够）
client_max_body_size 1m;

# API 与文件下载：关闭缓冲，进度实时透传（关键！否则前端进度条会卡死）
location ^~ /api/ {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 75s;
    add_header Cache-Control "no-store, no-cache, must-revalidate" always;
}

location ^~ /files/ {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # 大文件流式转发，省内存
    proxy_read_timeout 300s;
    add_header Cache-Control "public, max-age=3600" always;
}

location ^~ /static/ {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_cache_valid 200 1h;
    add_header Cache-Control "public, max-age=3600" always;
}

location / {
    proxy_pass http://127.0.0.1:8765;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_read_timeout 75s;
    add_header Cache-Control "no-cache, must-revalidate" always;
}

# 健康检查（EO 探活）
location = /healthz {
    proxy_pass http://127.0.0.1:8765/api/status;
    access_log off;
}

# 屏蔽常见扫描
location ~* /\.(git|env|htaccess) { return 404; }
location ~* \.(php|asp|aspx|jsp)$ { return 404; }
```

> 注意：把宝塔自动生成的 `location ^~ /` 默认块**替换**成上面的完整版本，避免重复 location 报错。
> 若提示 `duplicate location`，删掉宝塔原生成的那个 `location ^~ /` 块即可。

### 4. 保存并重载
配置文件保存后，宝塔会自动检测语法；若提示成功，点「重载配置」。

### 5. 本地验证反代
宝塔「终端」：
```bash
curl -s http://127.0.0.1/healthz
curl -s -H "Host: wb.jikegang.com" http://127.0.0.1/api/status
```
返回 JSON 即反代成功。

## 六、接入腾讯云 EdgeOne（EO）—— 隐藏源站 IP + 防护

> EO = CDN + WAF + DDoS 防护 + 隐藏源站 IP。用户访问 → EO → 你的 ECS。
> 详细接入以腾讯云 EO 控制台实际界面为准，这里是关键步骤与易错点。

### 1. EO 添加站点
- 腾讯云控制台 → EdgeOne → 添加站点 → 输入 `jikegang.com`
- 接入方式：一般选「CNAME 接入」（不影响主站 www）
- 按引导在 DNS 添加 EO 要求的验证记录，完成站点接入

### 2. 创建加速域名 wb.jikegang.com
- 在该站点下「域名服务」→ 添加加速域名：`wb.jikegang.com`
- 源站类型：**自有源站（IP）**
- 源站地址：填 ECS 公网 IP
- 回源端口：`80`（HTTP）
- 回源协议：HTTP（EO → 源站走 HTTP 即可，公网段是 EO 到你 ECS）
- 回源 Host：`wb.jikegang.com`

### 3. 改 DNS 为 EO 的 CNAME
EO 会给 wb.jikegang.com 分配一个 CNAME 目标（形如 `xxx.eo.dnse2.com`）。
到 DNS 解析处，把之前 `wb` 的 **A 记录改为 CNAME 记录**，指向 EO 分配的目标。

### 4. 配置缓存规则（最容易出错的一步！）

EO 控制台 → 域名 wb.jikegang.com →「缓存配置」→ 新增规则：

| 匹配条件 | 缓存行为 | 原因 |
|---|---|---|
| 路径前缀 `/api/` | **不缓存（遵循源站 / NO-CACHE）** | 抓取进度轮询实时性要求，缓存会导致进度条卡死、状态不同步 |
| 路径前缀 `/files/` | 缓存，遵循源站 / 短 TTL | 导出文件按需下载 |
| 路径前缀 `/static/` | 缓存 1 小时 | 静态图标 |
| 其余（`/`） | 遵循源站 | 主页要拿到最新版 |

> **`/api/*` 必须设为不缓存**，这是本项目最关键的 EO 配置。否则多人访问会互相看到旧进度。

### 5. 开启安全防护（推荐）
EO 控制台 →「安全」：
- 开启 **Web 防护 / WAF 基础规则**
- 开启 **Bot 管理**（拦截恶意爬虫，减轻源站压力）
- 开启 **DDoS 防护**
- 可选：**IP 黑白名单 / 频率限制**（防止单 IP 高频请求）

### 6. 安全组收紧（隐藏 IP 后加固源站）
接入 EO 后，建议在阿里云安全组把 `80` 端口的来源**限制为腾讯云 EO 的回源 IP 段**（腾讯云官方文档提供 IP 列表），不再对 `0.0.0.0/0` 放行 80。这样即使别人知道 ECS IP 也无法绕过 EO 直连。

## 八、数据位置与隐私边界

部署在 ECS 后的运行链路：
```
用户浏览器 → EO（隐藏源站IP+防护）→ 宝塔Nginx(80) → FastAPI(127.0.0.1:8765) → ECS磁盘
```

| 数据 | 是否经过 ECS | 存储位置 |
|---|---|---|
| Cookie | 经过 | **仅内存，不落盘**（任务结束/重启即消失） |
| 博文数据 | 经过 | ECS：`~/极客港微博导出/weibo.db`（Linux 下 paths.py 自动落家目录） |
| 导出文件 | 经过 | ECS：`~/微博导出/` |

- 这**不是**把桌面端搬到云端，而是 `server.py` 跑在服务器上，用户远程访问。
- 若要求「数据完全不经过 ECS」，需改用**内网穿透方案**，本次按阿里云方案 B 执行。

## 九、常见问题排查（workbuddy 备查）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 项目启动失败 | Python 版本低 / 依赖未装 | 管理器里看日志；确认 Python ≥ 3.10，重装 requirements.txt |
| 502 Bad Gateway | 后端 8765 没起来 | `curl 127.0.0.1:8765/api/status`；查 Python 项目日志 |
| 进度条卡死不动 | EO 或 Nginx 缓存了 `/api/*` | 确认 EO 缓存规则 `/api/` 不缓存；确认 Nginx `proxy_buffering off` |
| 反代配置报 duplicate location | 宝塔默认块与手写块重复 | 删掉宝塔自动生成的 `location ^~ /` 块 |
| EO 回源 5xx | 安全组没放行 EO 回源段 / 回源端口错 | 安全组放行 80；确认回源 IP/端口 |
| 抓取报「连续未取到数据」 | Cookie 失效 / 用户 ID 错 | 重新复制 Cookie；确认用户 ID 是纯数字或有效主页链接 |
