# 极客港 · 微博导出 v1.3.23

## 更新内容

### 修复：断点续传在「优雅停止」后失效（核心修复）
- **问题**：抓取中途点「停止」（或限流放弃），断点虽然提示"已保存可续传"，但下次
  勾选「续传」却**从第 1 页从头重抓**，断点完全失效——不仅浪费时间，重复请求
  m.weibo.cn 还大幅提升被限流/封号的风险。
- **原因**：停止时任务状态被写成 `done`，而续传判定只认 `running`。
- **修复**：新增 `stopped` 中间态。优雅停止/限流放弃时置 `stopped`，续传判定改为
  `running 或 stopped` 都从断点页续抓。

### 修复：网络异常后任务永久卡「running」
- **问题**：抓取中若网络中断/限流耗尽重试，异常会穿出主循环，导致任务状态**永久
  卡在 running**、且没有停止原因，界面上像是"还在抓"但实际已死。
- **修复**：主循环用 `try/finally` 兜底，无论正常结束、优雅停止还是异常中断，任务
  状态一定落库（写 `done` 或 `stopped`），并记录明确的停止原因。

### 修复：GUI 与网页版导出路径分裂
- **问题**：无 D 盘的 Windows 机器上，桌面端导出到 `~/微博导出`，网页版却导出到
  `~/Documents/微博导出`，同一用户两种模式数据分裂、找不到文件。
- **修复**：GUI 的导出目录统一委托给网页版同一实现，两种模式保证写到同一目录。

### 质量保障
- 新增 `test_regression_v1323.py` 回归测试，逐条验证上述三个修复（5 项断言全通过）。
- 全量测试 34 项通过：URL 解析 4、重试 5、空页 3、长文 4、视频 5、登录判定 8、回归 5。
